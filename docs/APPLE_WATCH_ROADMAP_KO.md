# Apple Watch 떨림 탐지 개발 로드맵

## 최종 목표

Apple Watch의 가속도계와 자이로스코프 데이터를 이용해 사용자가 어떤 동작을
하고 있더라도 떨림의 존재 가능성을 실시간으로 추정한다.

이 프로젝트의 최종 출력은 다음 세 상태로 정의한다.

- `tremor`: 떨림 증거가 충분함
- `non_tremor`: 떨림 증거가 충분하지 않음
- `uncertain`: 신호 품질이나 모델 신뢰도가 낮아 판단을 보류함

현재 데이터는 건강한 참가자가 의도적으로 만든 모사 떨림 데이터이므로,
현재 모델은 연구용 프로토타입이다. 환자 데이터와 임상 기준 라벨로 별도
검증하기 전에는 의료 진단이나 질환 판별에 사용할 수 없다.

## 전체 파이프라인

```text
Apple Watch IMU (accelerometer + gyroscope)
  -> 일정 주기로 수집 및 품질 검사
  -> 50 Hz 공통 시간축 리샘플링
  -> 3초 sliding window 생성
  -> 시간 영역 + 주파수 영역 특징 추출
  -> Core ML 모델 추론
  -> 연속 window 결과 결합
  -> tremor / non_tremor / uncertain
```

## 1단계: 연구용 베이스라인 확정

현재 저장소의 Random Forest B2를 첫 기준 모델로 사용한다. 이 모델은
가속도계와 자이로스코프의 시간 특징 및 3-12 Hz 주파수 특징을 함께 사용한다.

완료 조건:

- 동일한 명령으로 특징 추출, 학습 및 추론을 재현할 수 있음
- recording과 participant가 학습/평가 세트 사이에 섞이지 않음
- sensitivity, specificity, balanced accuracy, macro F1을 기록함
- 오류 recording과 참가자별 결과를 확인할 수 있음

## 2단계: Apple Watch 데이터 수집 앱

실제 배포 환경과 학습 환경의 차이를 줄이기 위해 Apple Watch에서 직접
데이터를 수집한다. 각 recording에는 다음 메타데이터를 함께 저장한다.

- 익명 participant ID와 session ID
- `tremor` 또는 `non_tremor` 라벨과 라벨 생성 방법
- 동작 종류
- 착용 손목과 Watch 방향
- sampling rate, recording 시작 시각, 누락 sample 수
- 기기 모델과 센서 설정

원시 센서 값과 메타데이터는 분리해 보존하고, 전처리된 데이터로 원본을
덮어쓰지 않는다. 동의 절차, 익명화, 보관 기간과 접근 권한도 수집 전에
정의한다.

## 3단계: 움직임에 강건한 데이터셋 구축

모델이 동작 자체를 떨림으로 오인하지 않도록 같은 참가자와 같은 동작에서
두 라벨을 모두 수집한다.

| 동작 | non-tremor | tremor |
| --- | ---: | ---: |
| 편하게 정지 | 필요 | 필요 |
| 팔 앞으로 뻗기 | 필요 | 필요 |
| 걷기 | 필요 | 필요 |
| 물 마시기 | 필요 | 필요 |
| 식기 사용 | 필요 | 필요 |
| 타이핑 또는 화면 조작 | 필요 | 필요 |
| 손목 돌리기 및 반복 동작 | 필요 | 필요 |

권장 수집 원칙:

- 참가자마다 모든 동작과 라벨 조합을 반복 측정함
- 여러 날짜와 세션에 나누어 수집함
- 강도와 주파수가 다른 떨림을 포함함
- 센서 위치와 수집 절차를 표준화함
- 특정 참가자, 동작 또는 세션이 한 라벨에만 나타나지 않게 함
- 실제 일반화를 주장하기 전 충분한 참가자와 독립 외부 데이터를 확보함

## 4단계: 누수 없는 평가

무작위 window 분할은 같은 recording의 거의 동일한 구간을 학습과 평가에
동시에 넣을 수 있으므로 사용하지 않는다.

평가는 다음 순서로 진행한다.

1. Leave-One-Subject-Out으로 보지 못한 사람에 대한 성능을 측정한다.
2. Leave-One-Activity-Out으로 보지 못한 동작에 대한 성능을 측정한다.
3. Leave-One-Session-Out으로 날짜와 착용 차이에 대한 성능을 측정한다.
4. 기존 공개 데이터로 학습하고 Apple Watch 데이터로 평가한다.
5. 최종 모델은 학습에 사용하지 않은 참가자와 세션에서 한 번 평가한다.

주평가지표는 recording-level balanced accuracy로 유지한다. Watch 사용성을
위해 false alarms per hour, 탐지 지연시간, `uncertain` 비율, 배터리 사용량도
함께 측정한다. 목표 수치는 추가 데이터의 난이도와 사용 시나리오를 확인한
뒤 검증 세트만 사용해 정한다.

## 5단계: 모델 개선

데이터가 충분해질 때까지 해석 가능한 작은 모델을 우선한다.

비교 순서:

1. Logistic Regression + 시간/주파수 특징
2. Random Forest + 시간/주파수 특징
3. 작은 1D CNN
4. raw signal과 spectrum을 결합한 dual-view 모델

각 모델은 동일한 participant 단위 split에서 비교한다. 평균 정확도만 보고
모델을 고르지 않고, 민감도·오탐·모델 크기·추론 시간·전력 소비를 함께 본다.

## 6단계: Core ML 및 Apple Watch 실시간 추론

Python 모델을 그대로 Watch에서 실행하지 않는다. 최종 특징 계산을 Swift로
동일하게 구현하고, 변환 가능한 작은 모델을 Core ML 형식으로 내보낸다.

Watch 추론 요구사항:

- 센서 sample을 ring buffer에 저장함
- 3초 window와 사전에 정한 stride를 사용함
- 학습 때와 동일한 단위, 리샘플링 및 특징 계산을 적용함
- 연속된 여러 window가 기준을 넘을 때만 떨림 이벤트를 생성함
- 누락 sample, 심한 충격 및 비정상 sampling에는 `uncertain`을 반환함
- 휴대폰이나 서버 연결 없이 가능한 범위에서 on-device로 처리함

Python과 Swift가 동일한 fixture CSV에서 동일한 특징과 예측을 만드는지
자동 테스트한다. 허용 오차를 넘으면 Watch 배포를 진행하지 않는다.

## 7단계: 실제 사용 환경 검증

- 기기에서의 추론 지연시간과 메모리 사용량 측정
- 연속 센서 수집 시 배터리 소모 측정
- 걷기, 양치, 박수, 차량 진동 등 대표적인 오탐 상황 시험
- Watch 착용 방향과 손목 변경에 대한 민감도 시험
- 긴 연속 기록에서 시간당 오탐 횟수 측정
- 모델 버전, 특징 버전 및 학습 데이터 버전을 함께 기록
