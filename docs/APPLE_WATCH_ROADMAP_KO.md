# 웨어러블 떨림 탐지 개발 로드맵

## 최종 목표

손목에 착용하는 IMU 기기의 가속도계와 자이로스코프 데이터를 이용해 사용자가
어떤 동작을 하고 있더라도 떨림의 존재 가능성을 실시간으로 추정한다. 1안은
Apple Watch를 사용하고, 연결과 연속 수집이 충분히 안정적이지 않으면 2안으로
IMU 센서와 3D 프린팅 케이스를 사용한 독립 기기를 제작한다.

이 프로젝트의 최종 출력은 다음 세 상태로 정의한다.

- `tremor`: 떨림 증거가 충분함
- `non_tremor`: 떨림 증거가 충분하지 않음
- `uncertain`: 신호 품질이나 모델 신뢰도가 낮아 판단을 보류함

현재 데이터는 건강한 참가자가 의도적으로 만든 모사 떨림 데이터이므로,
현재 모델은 연구용 프로토타입이다. 환자 데이터와 임상 기준 라벨로 별도
검증하기 전에는 의료 진단이나 질환 판별에 사용할 수 없다.

## 구현 전략: 1안과 2안

### 1안: Apple Watch

Apple Watch의 IMU와 watchOS 앱을 사용한다. 별도 하드웨어 제작이 필요 없고
Core ML을 이용한 on-device 추론까지 하나의 기기에서 구성할 수 있다는 장점이
있다. 먼저 센서 수집, iPhone과의 데이터 전달, 백그라운드 동작 및 장시간
연속 실행의 안정성을 검증한다.

다음 조건을 모두 충족하면 1안을 계속 사용한다.

- 목표 sampling rate로 연속 수집할 때 누락률을 측정할 수 있고 허용 범위 이내임
- 연결이 끊겨도 Watch에 임시 저장한 뒤 데이터를 복구할 수 있음
- 반복 실험에서 recording 시작·종료와 파일 전달이 안정적으로 동작함
- 실시간 추론 중 발열과 배터리 소모가 사용 시나리오에 적합함

### 2안: 직접 제작하는 IMU 웨어러블

1안이 수집 안정성 또는 연결 요구사항을 만족하지 못하면 IMU 센서,
마이크로컨트롤러, 배터리 및 3D 프린팅 손목 케이스로 독립 기기를 제작한다.
기기는 연결이 끊겨도 원시 데이터를 로컬에 저장하고, 필요할 때 BLE 또는
유선 연결로 전송할 수 있어야 한다.

2안의 설계 요구사항:

- 3축 accelerometer와 3축 gyroscope를 동일한 sampling rate로 수집함
- 각 sample에 단조 증가 timestamp를 기록함
- 센서 range, 단위, sampling rate와 firmware 버전을 metadata에 저장함
- 통신 장애와 관계없이 로컬 저장을 계속함
- 배터리 잔량, 누락 sample 및 저장 오류를 확인할 수 있음
- 센서가 손목에서 흔들리지 않도록 케이스와 스트랩을 고정함
- USB 충전·데이터 접근과 전원 스위치를 고려해 3D 케이스를 설계함
- 센서 축 방향과 착용 방향을 케이스 및 데이터에 명확히 표시함

부품은 위 요구사항과 실제 조달 가능성을 확인한 뒤 확정한다. 특정 센서나
보드를 먼저 고정하지 않고 sampling 안정성, 저장 공간, 전력 소비와 크기를
측정해 선택한다.

### 전환 판단

Apple Watch 연결과 안정적인 센서 수집 검증에는 최대 2개 개발일만 사용한다.
작업을 시작한 시점부터 누적 2개 개발일 안에 연결·연속 수집·데이터 전달의
핵심 병목을 해결하지 못하면 Apple Watch 추가 디버깅을 중단하고 즉시 2안으로
전환한다. 전환 시점에는 실패 증상, 시도한 해결 방법과 남은 문제를 짧게
기록해 같은 문제를 반복 조사하지 않도록 한다.

2일 이내에 연결되더라도 누락률·복구 가능성·배터리·전송 성공률이 요구사항을
충족해야 1안을 유지한다. 두 안을 동시에 장기간 개발해 일정이 분산되지 않도록
한다.

## 공통 데이터 파이프라인

```text
Apple Watch 또는 직접 제작한 IMU 기기
  -> 일정 주기로 수집 및 품질 검사
  -> 50 Hz 공통 시간축 리샘플링
  -> 3초 sliding window 생성
  -> 시간 영역 + 주파수 영역 특징 추출
  -> 기기에 맞는 경량 모델 추론
  -> 연속 window 결과 결합
  -> tremor / non_tremor / uncertain
```

## 1단계: 연구용 베이스라인 확정

현재 저장소의 Random Forest B2를 첫 기준 모델로 사용한다. 이 모델은
가속도계와 자이로스코프의 시간 특징 및 3-12 Hz 주파수 특징을 함께 사용한다.

완료 조건:

- 동일한 명령으로 특징 추출, 학습 및 추론을 재현할 수 있음
- recording과 participant가 학습/평가 세트 사이에 섞이지 않음
- sensitivity, specificity, balanced accuracy, macro F1을 기록함
- 오류 recording과 참가자별 결과를 확인할 수 있음

## 2단계: 착용 기기 기술 검증 및 데이터 수집

먼저 Apple Watch 수집 앱으로 연결과 연속 수집을 검증한다. 통과하면 Watch를
수집·추론 기기로 사용하고, 실패하면 독립 IMU 기기를 제작해 같은 데이터
schema를 사용한다. 어느 기기를 사용하든 각 recording에는 다음 메타데이터를
함께 저장한다.

- 익명 participant ID와 session ID
- `tremor` 또는 `non_tremor` 라벨과 라벨 생성 방법
- 동작 종류
- 착용 손목과 기기 방향
- sampling rate, recording 시작 시각, 누락 sample 수
- 기기 종류, 기기 모델, firmware/app 버전과 센서 설정

원시 센서 값과 메타데이터는 분리해 보존하고, 전처리된 데이터로 원본을
덮어쓰지 않는다. 동의 절차, 익명화, 보관 기간과 접근 권한도 수집 전에
정의한다.

## 3단계: 움직임에 강건한 데이터셋 구축

모델이 동작 자체를 떨림으로 오인하지 않도록 같은 참가자와 같은 동작에서
두 라벨을 모두 수집한다.

| 동작 | non-tremor | tremor |
| --- | ---: | ---: |
| 편하게 정지 | 필요 | 필요 |
| 팔 앞으로 뻗기 | 필요 | 필요 |
| 걷기 | 필요 | 필요 |
| 물 마시기 | 필요 | 필요 |
| 식기 사용 | 필요 | 필요 |
| 타이핑 또는 화면 조작 | 필요 | 필요 |
| 손목 돌리기 및 반복 동작 | 필요 | 필요 |

권장 수집 원칙:

- 참가자마다 모든 동작과 라벨 조합을 반복 측정함
- 여러 날짜와 세션에 나누어 수집함
- 강도와 주파수가 다른 떨림을 포함함
- 센서 위치와 수집 절차를 표준화함
- 특정 참가자, 동작 또는 세션이 한 라벨에만 나타나지 않게 함
- 실제 일반화를 주장하기 전 충분한 참가자와 독립 외부 데이터를 확보함

## 4단계: 누수 없는 평가

무작위 window 분할은 같은 recording의 거의 동일한 구간을 학습과 평가에
동시에 넣을 수 있으므로 사용하지 않는다.

평가는 다음 순서로 진행한다.

1. Leave-One-Subject-Out으로 보지 못한 사람에 대한 성능을 측정한다.
2. Leave-One-Activity-Out으로 보지 못한 동작에 대한 성능을 측정한다.
3. Leave-One-Session-Out으로 날짜와 착용 차이에 대한 성능을 측정한다.
4. 기존 공개 데이터로 학습하고 최종 착용 기기 데이터로 평가한다.
5. 최종 모델은 학습에 사용하지 않은 참가자와 세션에서 한 번 평가한다.

주평가지표는 recording-level balanced accuracy로 유지한다. Watch 사용성을
위해 false alarms per hour, 탐지 지연시간, `uncertain` 비율, 배터리 사용량도
함께 측정한다. 목표 수치는 추가 데이터의 난이도와 사용 시나리오를 확인한
뒤 검증 세트만 사용해 정한다.

## 5단계: 모델 개선

데이터가 충분해질 때까지 해석 가능한 작은 모델을 우선한다.

비교 순서:

1. Logistic Regression + 시간/주파수 특징
2. Random Forest + 시간/주파수 특징
3. 작은 1D CNN
4. raw signal과 spectrum을 결합한 dual-view 모델

각 모델은 동일한 participant 단위 split에서 비교한다. 평균 정확도만 보고
모델을 고르지 않고, 민감도·오탐·모델 크기·추론 시간·전력 소비를 함께 본다.

## 6단계: 착용 기기 실시간 추론

### 1안: Apple Watch 추론

Python 모델을 그대로 Watch에서 실행하지 않는다. 최종 특징 계산을 Swift로
동일하게 구현하고, 변환 가능한 작은 모델을 Core ML 형식으로 내보낸다.

Watch 추론 요구사항:

- 센서 sample을 ring buffer에 저장함
- 3초 window와 사전에 정한 stride를 사용함
- 학습 때와 동일한 단위, 리샘플링 및 특징 계산을 적용함
- 연속된 여러 window가 기준을 넘을 때만 떨림 이벤트를 생성함
- 누락 sample, 심한 충격 및 비정상 sampling에는 `uncertain`을 반환함
- 휴대폰이나 서버 연결 없이 가능한 범위에서 on-device로 처리함

Python과 Swift가 동일한 fixture CSV에서 동일한 특징과 예측을 만드는지
자동 테스트한다. 허용 오차를 넘으면 Watch 배포를 진행하지 않는다.

### 2안: 독립 IMU 기기 추론

마이크로컨트롤러의 메모리와 연산 성능을 기준으로 특징 계산과 모델을
경량화한다. 기기 내 추론이 어렵다면 원시 데이터를 안정적으로 저장·전송하는
것을 우선하고, 연결된 iPhone에서 추론한다. 최종 실행 위치는 정확도뿐 아니라
지연시간, 배터리, 연결 의존성과 개인정보 보호를 함께 비교해 결정한다.

## 7단계: 실제 사용 환경 검증

- 기기에서의 추론 지연시간과 메모리 사용량 측정
- 연속 센서 수집 시 배터리 소모 측정
- 걷기, 양치, 박수, 차량 진동 등 대표적인 오탐 상황 시험
- 기기 착용 방향과 손목 변경에 대한 민감도 시험
- 직접 제작 기기는 케이스 고정력, 착용감, 내구성과 센서 축 정렬을 시험
- 긴 연속 기록에서 시간당 오탐 횟수 측정
- 모델 버전, 특징 버전 및 학습 데이터 버전을 함께 기록

## 바로 다음 작업

1. 두 기기에서 공통으로 사용할 CSV와 metadata schema를 확정한다.
2. Apple Watch에서 50 Hz 수집, 로컬 임시 저장과 파일 내보내기를 구현한다.
3. 최대 2개 개발일 동안 연결과 연속 수집 병목을 해결하고 시험 결과를 기록한다.
4. 2일 안에 해결하지 못하면 즉시 2안으로 전환하고, 해결했다면 누락률·전송
   성공률·배터리 소모를 기준으로 1안 유지 여부를 결정한다.
5. 2안이면 IMU·보드·배터리를 선정하고 breadboard prototype부터 검증한다.
6. 전자부품과 firmware가 확정된 후 손목 케이스를 3D 프린팅한다.
7. 동작별 수집 프로토콜과 참가자 동의 절차에 따라 데이터를 수집한다.
8. 첫 착용 기기 데이터를 Python 파이프라인으로 읽어 domain shift를 측정한다.
9. 데이터가 쌓이면 activity-aware 평가를 자동화한다.
